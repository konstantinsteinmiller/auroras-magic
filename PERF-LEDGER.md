# Perf ledger — Auroras Magic

Every optimisation is a hypothesis until it beats the un-optimised build on a
throttled or real device (`web-game-performance-optimize`). Record the result
here, including null results, so a rejected idea is not tried again next month.

## Seams in place (from the jam build and the migration)

| Seam | Where | Notes |
| --- | --- | --- |
| One RAF, fixed 1/120 s sim step, render once per frame | `views/GameScene.vue` | Identical duel at 30 or 144 Hz; dt clamped to 0.25 s. |
| Adaptive quality `S.q`, three tiers with hysteresis | `game/duel/quality.ts`, called from `views/AppScene.vue`; tests in `tests/duel/quality.test.ts` | `0` thrift drops cel bands, shade stripes, aura, hair locks and half the grass; the silhouettes stay. `1` is the authored look. `2` sparkle spends measured headroom on draw work only (2026-09-23, E2 below). The DROP reads the frame interval (a missed vsync is the one thing work-per-frame cannot see); the CLIMBS read `S.fw`, the work inside the RAF callback, because a 60 Hz panel reports 16.7 ms whether the frame cost 0.7 ms or 15 ms. Renderers scale tier 2 on `S.qx`, an eased mix, never on `S.q > 1`. |
| DPR capped at 2 — and lower on a phone that cannot fill it (2026-09-24) | `game/renderScale.ts` → `backingDpr()`, read by `AppScene.resize`, the boot bake in `useAssets` and `pageDecor`'s bake; tests in `tests/duel/renderScale.test.ts` | Live and downward only: once `S.q` is 0 and two 1.2 s windows in a row have a median interval over 40 ms, the cap drops in ONE jump of `√(33.3 ms / median)` (at least one 1.2× notch, floor 0.7). Scene changes and drops each settle 2 s; paused/hidden/boot frames never count. Stored in `am.renderCap` so the next boot starts there; 20 s at ≤ 18.5 ms earns the NEXT boot one notch back. `deviceMemory` ≤ 2 GB and nothing stored starts at 1. Fires `render_scale` analytics on every drop. |
| Particle pool: one `Float32Array`, ring allocator, colour-batched draw, zero allocation per frame | `game/duel/fx.ts` | Hard cap of 360 particles. |
| Baked arena (island, cloud band, sky gradient), rebuilt only when the quantised device scale changes; primed behind the splash | `game/duel/arena.ts`, `use/useAssets.ts` | |
| Cached duel backdrop on the thrift tier (2026-09-24, E4) | `game/duel/backdrop.ts`, hooked from `render.ts` (`drawBackdropPad` / `drawBackdrop`); tests in `tests/duel/backdrop.test.ts` | At `S.q === 0` the page, the sky (wash, rainbow, clouds) and the PAINTED island are composed into one canvas on the resting camera's device-pixel grid and blitted; portrait includes the page under the pad. Recomposed only when the page's version moves (`duelPageVersion`: a spell, a re-bake, a reset), `S.sky` crosses a 64th, the clouds drift one device px, a painting arrives, the theme / versus / layout / pad foot changes. The DRAWN island sways and stays live. Released on every page reset (`onDuelPageReset`). |
| Reactivity firewall: `S` is a plain object; the HUD gets a copy of the values that changed, and HP bars and the forming ring are written directly to the DOM | `use/useDuelHud.ts` | |
| Probe + A/B harness | `use/usePerfProbe.ts`, `use/perfVariants.ts`, `scripts/perf-ab.mjs`, `components/atoms/FPerfMeter.vue` (debug) | `?perfprobe=1`. `perf-ab.mjs --drive duel` walks a finished save into the finale duel, wears every keepsake, waits a fixed 14 s for the quality tier to settle, resets the probe and then casts a fresh pair of runes every 600 ms — without it the runner records the boot screen and A/Bs an idle page. It also refuses a served `<title>` that is not Auroras Magic, waits for a quiet machine before each rep (ported from `perf-builds.mjs`), reports the tier each arm ran at and how many times it flipped, and relaunches a browser that dies mid-session. |

## Seams added by story stage S1 (the wipe, story-spec §9.3, §9.15)

| Seam | Where | Notes |
| --- | --- | --- |
| Analytic coverage model, no `getImageData` in the wipe path | `game/restore/mask.ts` | 24×14 save/threshold grid over a 96×56 sample lattice. Every stamp is accounted with the baked stamp's own falloff. |
| Dust composited ONCE per sector visit, then erased in place | `game/restore/dust.ts` | Drain (`saturation`), ink (`multiply`) and grain (`overlay`) are done when the sector opens. A frame is two blits plus the stamps. §9.4 had budgeted a live composite every frame. |
| Pre-baked 96×96 soft stamp, no `ctx.filter` | `game/restore/dust.ts` | Re-baked only when the brush's core share changes (a resize). |
| One stamp batch per RAF, not per `pointermove` | `game/restore/brush.ts` | Coalesced samples buffer; `flush()` once per frame. |
| Reveal wave clips the dust instead of erasing it | `game/restore/wipe.ts` | A full-canvas `destination-out` per wave frame cost ~3.8 ms. The clip costs nothing extra. |
| Sector canvases at the resolution the sector is DRAWN at (0.5–1 × 1152×672, ¼ steps; 0.5 on `S.q = 0`) | `game/restore/wipe.ts` | Released when the scene ends. |
| Frame-cost probe: mask + dust work per frame, with the phase of the worst frame | `game/restore/wipe.ts` → `__wipe.perf()` | |
