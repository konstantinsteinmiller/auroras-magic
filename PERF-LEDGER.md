# Perf ledger — Auroras Magic

Every optimisation is a hypothesis until it beats the un-optimised build on a
throttled or real device (`web-game-performance-optimize`). Record the result
here, including null results, so a rejected idea is not tried again next month.

## Seams in place (from the jam build and the migration)

| Adaptive quality `S.q`, three tiers with hysteresis | `game/duel/quality.ts`, called from `views/AppScene.vue`; tests in `tests/duel/quality.test.ts` | `0` thrift drops cel bands, shade stripes, aura, hair locks and half the grass; the silhouettes stay. `1` is the authored look. `2` sparkle spends measured headroom on draw work only (2026-09-23, E2 below). The DROP reads the frame interval (a missed vsync is the one thing work-per-frame cannot see); the CLIMBS read `S.fw`, the work inside the RAF callback, because a 60 Hz panel reports 16.7 ms whether the frame cost 0.7 ms or 15 ms. Renderers scale tier 2 on `S.qx`, an eased mix, never on `S.q > 1`. |
| DPR capped at 2 | `GameScene.resize` | |

It also refuses a served `<title>` that is not Auroras Magic, waits for a quiet machine before each rep (ported from `perf-builds.mjs`), reports the tier each arm ran at and how many times it flipped, and relaunches a browser that dies mid-session. |

## Seams added by story stage S1 (the wipe, story-spec §9.3, §9.15)

| Seam | Where | Notes |
| --- | --- | --- |
| Analytic coverage model, no `getImageData` in the wipe path | `game/restore/mask.ts` | 24×14 save/threshold grid over a 96×56 sample lattice. Every stamp is accounted with the baked stamp's own falloff. |
| Dust composited ONCE per sector visit, then erased in place | `game/restore/dust.ts` | Drain (`saturation`), ink (`multiply`) and grain (`overlay`) are done when the sector opens. A frame is two blits plus the stamps. §9.4 had budgeted a live composite every frame. |
| Pre-baked 96×96 soft stamp, no `ctx.filter` | `game/restore/dust.ts` | Re-baked only when the brush's core share changes (a resize). |
| One stamp batch per RAF, not per `pointermove` | `game/restore/brush.ts` | Coalesced samples buffer; `flush()` once per frame. |
| Reveal wave clips the dust instead of erasing it | `game/restore/wipe.ts` | A full-canvas `destination-out` per wave frame cost ~3.8 ms. The clip costs nothing extra. |
| Sector canvases at the resolution the sector is DRAWN at (0.5–1 × 1152×672, ¼ steps; 0.5 on `S.q = 0`) | `game/restore/wipe.ts` | Released when the scene ends. |
| Frame-cost probe: mask + dust work per frame, with the phase of the worst frame | `game/restore/wipe.ts` → `__wipe.perf()` | |

## Experiments

| Date | Hypothesis | Arms | Result | Verdict |
| --- | --- | --- | --- | --- |
| 2026-09-18 | *S1 wipe:* mask + dust stays ≤ 3 ms/frame for a standard sector (§9.3.3). | headless Chrome: 1280×720 @1×, 320×658 @2× touch, 320×658 @2× with CPU ×4 | Wipe frames: avg 0.09–0.13 ms, p95 0.2–0.4 ms, max 0.9 ms unthrottled. At CPU ×4: avg 0.9–1.0 ms, p95 1.8–2.1 ms, max 4.2 ms. Worst one-off frames at CPU ×4: 30 ms on the scene's first frame (the GPU upload of the fresh bakes, hidden under the page dip) and 23 ms once in the restored view (after the save write, most likely GC) | **holds** — the steady wipe p95 is within budget even at ×4. The live-composite arm §9.15 queued was never needed: baking the dust once took the per-frame composite off the table |
| 2026-09-18 | *S1 reveal wave:* erasing the dust with a growing stamp each frame is affordable. | per-frame full-canvas `destination-out` vs a clip of the dust draw | erase: one 3.8 ms frame unthrottled; clip: the wave frames are gone from the top of the list | **rejected** the erase — the clip ships |
| 2026-09-19 | *S8 release baseline:* every scene holds 60 fps on the mid-range Android proxy with headroom, so nothing needs optimising. | `scripts/perf-scenes.mjs` on the built web bundle, headed Chrome, CPU ×4, DPR 2, 915×412 landscape and 412×915 portrait; duel 60 s (the 10-5 boss, both sides casting the late kit), map, boss wipe, versus, wardrobe 15 s each | Landscape p95 work per frame: duel 3.8 ms (p99 5.3), map 3.9, wipe 2.4, versus 3.5, wardrobe 3.0. Portrait: 3.4 / 4.1 / 2.6 / 4.2 / 3.5. RAF interval p95 17.4–17.8 ms everywhere, zero long tasks, heap slope within ±1 kB/frame. Boot (gzip, Fast 3G, CPU ×4): 4.1 s to the splash clearing | **already fast enough.** The worst p95 is about 25 % of the 16.7 ms budget; per the skill, nothing is changed. `desktop-proxy-only` until a real phone confirms it |
| 2026-09-19 | *Painted-art census (scoped-art-invalidation):* with the art layer on, a painting's arrival re-bakes only what was built from it. | the same run with synthetic paintings, `art=off` vs `art=on` | Canvases created over the whole session: 59 off vs 126 on. The extra 67 are one-time bakes (tint masks, the page's thumbnails, the tinted gift strips) that track scene visits, not arrivals. Frame p95 unchanged (duel 3.6 vs 3.0, map 3.7 vs 3.9, wipe 2.8 vs 2.4 ms). Boot 4.2 s vs 5.4 s: the splash holding for the first screen's paintings, as designed, capped at 4 s | **holds** — no invalidation storm. Re-run the census when real paintings land, since they are heavier |
| 2026-09-23 | **E1 — the tier hysteresis was reading a signal that cannot answer the question.** `S.q` restored only below a smoothed 15 ms frame INTERVAL. A 60 Hz panel reports 16.7 ms whether the frame cost 0.7 ms or 15 ms, so that line is a test of refresh rate, not of strength, and on 60 Hz it can never be true. Hypothesis: the boot's own slow frames drop every 60 Hz session to tier 0 and it never comes back, and restoring on WORK per frame instead costs under 1 % of the budget. | `perf=quality-legacy` (the two original lines, verbatim) vs `perf=sparkle-legacy` (the new controller, tier capped at 1). `pnpm perf:ab --drive duel` on a built bundle served gzipped, headed Chrome, the finale boss with every keepsake worn, a fresh pair of runes cast every 600 ms, a fixed 14 s settle then 900 frames a rep, 4 reps interleaved. Desktop 520×1000 DPR 1 unthrottled; mid-range proxy 915×412 DPR 2 touch at CPU ×4. | **The hypothesis was confirmed before the arms were compared:** in the legacy arm, unthrottled, `fdt` sat at 0.0167 and `fw` at 0.0007–0.0011 s — 96 % of the frame budget idle — and `q` stayed **0 for the whole of every rep**. Every 60 Hz session was played in thrift: no cel bands, no limb or neck shade stripes, no dread aura, one hair lock. Desktop workP95, 4 reps: A 1.700 / 1.700 / 1.700 / 1.700 ms → B 1.800 / 1.800 / 1.900 / 1.800 ms (median **1.700 → 1.800, +5.9 %**); p99 2.0 → 2.2; interval p95 16.90 → 16.90; zero long tasks in both; heap flat. Throttled proxy: **both arms sat at `q = 0`, zero flips, in every rep** — the weak device does not qualify for the restore, so the arms are code-identical there and the run is an A-versus-A. | **ships.** +0.1 ms of a 16.7 ms frame — 0.6 % of the budget — buys back the game's entire authored look on every 60 Hz display. The runner prints “regression — revert” because it is written for optimisations; this is fidelity that was authored, paid for and then never delivered. The weak device is untouched. The DROP to 0 still reads the interval, unchanged at 24 ms: a missed vsync is GPU backpressure, and work-per-frame is the one number that cannot see it |
| 2026-09-23 | **E2 — retention-roadmap item 17, the sparkle tier.** A third tier (`S.q = 2`) that spends measured headroom on DRAW work only — a second rank of grass, more motes, a wider dread halo, an outer spark ring on a forming rune, two more steps on every keepsake glow, three more ghosts on the Pet Star's trail. **Gate registered before measuring:** (a) a device that cannot hold the frame never enters it, (b) where it is entered the cost is bounded and the frame budget still has room, (c) no RAF-interval, long-task or heap regression, (d) the tier settles instead of flickering. It ships only if all four hold. | `perf=sparkle-legacy` (cap at 1) vs the shipping path (up to 2), same harness as E1; desktop 5 reps × 900 frames, proxy 4 reps × 700 frames. | **(a)** Throttled proxy at CPU ×4: `fw` 8–15 ms of a 16.7 ms budget, and **both arms sat at `q = 0` with zero flips in all 8 runs** — the tier is never offered, the arms are code-identical, and the −1.0 % median difference is noise. **(b)** Desktop workP95: A 1.8 / 2.0 / 2.0 / 2.1 / 2.3 (median **2.000**) → B 2.0 / 2.0 / 2.2 / 2.1 / 2.2 (median **2.100**) = **+0.1 ms, +5.0 %**, which is ONE tick of the probe's resolution; p99 2.4 → 2.5 ms; ~14.6 ms of the 16.7 ms budget still free. **(c)** interval p95 16.90 ms in both, 1 long task in both, heap flat. **(d)** arm B held tier 2 with `qx = 1` for the whole recording in 3 of 5 reps; the other two dipped on a contended box, in the reps where arm A dipped to tier 0 as well. | **ships.** All four gates hold. Two numbers are worth keeping: an earlier 5-rep desktop run with NO keepsakes equipped came out 1.900 → 1.800 — the opposite sign — which is the honest size of this effect: **the tier's cost is at or below the measurement floor**, and any single run can report it either way. Quote the keepsake run, because it is the only one that draws the Pet Star trail and the soft glows at all |
| 2026-09-23 | **Noise floor of a throttled A/B on this machine** (not a change — a measurement about the instrument). | The E1 proxy run, in which both arms were code-identical (`q = 0`, zero flips, all 8 runs), scored as an ordinary experiment. | It reported **+39.7 %** for B, with workP95 drifting 28.5 → 89.3 ms and long tasks 55 → 358 across four interleaved reps while another agent session used the box (CPU 26–49 %). A tighter re-run was abandoned: the gate could not get the box below 38 % for long enough, which is itself the point. | **an A-versus-A that produced a confident regression.** At CPU ×4 on a shared machine the noise floor is tens of per cent, so no throttled A/B here can resolve anything smaller — interleaving handles drift, not a neighbour who starts compiling in rep 3. `perf-ab.mjs` now waits for a quiet box before each rep and stamps each row with the load it ran at (ported from `perf-builds.mjs`), and it reports the quality tier each arm actually ran at, which is what exposed this one as an A/A. Also note: the proxy's `fw` of 8–15 ms does not reproduce the S8 baseline row's 3.8 ms p95 — contention explains part of it, and the painted-art pass landed after that baseline. **The S8 proxy baseline needs re-measuring on a quiet box before it is quoted again.** |
